# 2.10 不仅是相位对齐：频率同步的秘密

## 两个时钟，两个"心跳"

想象两个跑步者在跑道上跑步。

**情况一**：两个人跑得一样快，但位置不同。

- 跑步者A在起点
- 跑步者B在起点前10米

这是**相位偏差**。解决方案：让B后退10米，两人就同步了。

**情况二**：两人位置相同，但速度不同。

- 跑步者A每秒跑10米
- 跑步者B每秒跑10.1米

这是**频率偏差**。即使现在位置相同，10秒后B就会领先1米。

PTP从时钟面临的就是这两种问题：

- **相位同步（Synchronization）**：调整当前时间
- **频率同步（Syntonization）**：调整走时速度

上一节，我们讨论了相位同步。这一节，我们深入探讨**频率同步**。

---

## 为什么频率同步如此重要？

### 场景一：失去主时钟

假设从时钟同步到主时钟，相位偏差已经接近0。

突然，主时钟故障，从时钟失去参考。

如果从时钟没有频率同步：
- 本地晶振频率偏差：+10ppm
- 每秒累积误差：10微秒
- 每分钟累积误差：600微秒
- 每小时累积误差：36毫秒

**保持模式（Holdover）**：从时钟失去主时钟后，依靠本地晶振"守时"。

如果频率已同步：
- 知道频率补偿值：-10ppm
- 即使失去主时钟，仍可以应用这个补偿
- 误差累积速度降低100倍甚至更多

### 场景二：减少同步报文频率

如果从时钟的频率已经同步到主时钟：
- 频率偏差接近0
- 相位偏差累积很慢
- 可以减少Sync报文频率

**好处**：
- 降低网络负载
- 降低CPU负载
- 仍能保持精度

### 场景三：透明时钟的频率一致性

透明时钟需要测量驻留时间。如果透明时钟的频率与主时钟不同：
- 测量的驻留时间会有误差
- 这个误差会传播到下游设备

**要求**：透明时钟的Local Clock最好频率同步到主时钟。

## PTP中的频率同步机制

### 方法一：从相位偏差推导频率偏差

**原理**：通过多次测量相位偏差，计算变化率。

**公式**：

```
频率偏差 ≈ (offsetₙ - offsetₙ₋₁) / (Tₙ - Tₙ₋₁)
```

**示例**：

```
T₁ = 1000秒，offset₁ = +100ns
T₂ = 1001秒，offset₂ = +110ns

频率偏差 = (110ns - 100ns) / (1001秒 - 1000秒)
        = 10ns/秒
        = 10ppb
```

**实现**：

从时钟持续测量offsetFromMaster，使用滑动窗口平均或低通滤波，提取频率偏差。

**优点**：
- 不需要额外报文
- 实现简单

**缺点**：
- 需要多次测量，收敛慢
- 受网络抖动影响

### 方法二：直接频率测量

**原理**：直接比较主时钟和从时钟的频率。

**Sync报文携带的信息**：

- originTimestamp：Sync报文的发送时间
- correctionField：各种校正值

**从时钟的处理**：

1. 接收Sync报文，记录接收时间t2
2. 计算校正后的主时钟发送时间：
   ```
   correctedMasterTime = originTimestamp + correctionField + meanDelay
   ```
3. 记录两次Sync的correctedMasterTime和本地时间
4. 计算频率比：
   ```
   frequencyRatio = (本地时间间隔) / (主时钟时间间隔)
   ```

**示例**：

```
Sync 1:
- 本地接收时间：t₂₁ = 1000.000000100秒
- 主时钟发送时间（校正后）：T₁ = 1000.000000000秒

Sync 2:
- 本地接收时间：t₂₂ = 1001.000000110秒
- 主时钟发送时间（校正后）：T₂ = 1001.000000000秒

本地时间间隔 = t₂₂ - t₂₁ = 1.000000010秒
主时钟时间间隔 = T₂ - T₁ = 1.000000000秒

频率比 = 1.000000010 / 1.000000000 = 1.000000010
频率偏差 = 频率比 - 1 = 10ppb
```

**优点**：
- 精度高
- 收敛快

**缺点**：
- 需要准确的meanDelay测量
- 需要准确的时间戳

### 方法三：累积频率传输（可选特性16.10）

这是IEEE 1588-2019的一个可选特性，提供更精确的频率同步。

**核心概念**：

- **neighborRateRatio**：邻居频率比（本端口频率 / 对端频率）
- **cumulativeRateRatio**：累积频率比（主时钟频率 / 本端口频率）

**传输方式**：

使用CUMULATIVE_RATE_RATIO TLV，携带累积频率比信息。

**更新规则**：

```
cumulativeRateRatio（出口） = cumulativeRateRatio（入口） × neighborRateRatio
```

**应用**：

- 透明时钟校正驻留时间时，考虑累积频率比
- 下游设备可以更准确地恢复频率

## 频率补偿的实现

### 软件实现

**方法**：维护一个频率补偿值，每次读取本地时钟时应用。

```c
double frequency_adjustment = 1.0 + frequency_offset;

Timestamp get_adjusted_time() {
    Timestamp raw_time = read_hardware_counter();
    return raw_time * frequency_adjustment + phase_offset;
}
```

**精度限制**：

- 浮点运算精度（通常足够）
- 读取频率（影响实时性）

### 硬件实现

**方法一：数控振荡器（NCO）**

使用数字控制的方式调整振荡器频率。

**原理**：

```
NCO输出频率 = 参考频率 × (控制字 / 2^N)
```

其中：
- N是NCO的位数（如32位、48位）
- 控制字是可编程的

**示例**：

```
参考频率 = 125 MHz
N = 32

控制字 = 2^32 × (1 + frequency_adjustment)
```

**精度**：

对于32位NCO，频率调整粒度约为：

```
粒度 = 125 MHz / 2^32 ≈ 0.03 Hz ≈ 0.24 ppb
```

**方法二：锁相环（PLL）**

使用PLL锁定到参考信号。

**PTP场景**：

如果主时钟提供1PPS信号，从时钟可以用PLL锁定这个信号，实现频率同步。

### 混合实现

**软件维护频率补偿值，硬件维护计数器**。

这是最常见的实现方式，平衡精度和成本。

## 频率同步与相位同步的关系

### 两种同步的定义

**相位同步（Synchronization）**：
- 定义：两个时钟的时间基准一致
- 表现：对于同一事件，两个时钟记录的时间相同
- 要求：相位偏差 < 阈值

**频率同步（Syntonization）**：
- 定义：两个时钟的走时速度一致
- 表现：两个时钟的秒长相同
- 要求：频率偏差 < 阈值

### 可以只频率同步吗？

**可以！** 某些应用只需要频率同步，不需要相位同步。

**场景一：无线通信**

基站之间需要频率同步，保证载波频率一致。

但不需要知道"现在几点"，只需要知道"每秒多长"。

**场景二：数据采样**

多个数据采集设备需要同步采样率，但不需要同步绝对时间。

### 可以只相位同步吗？

**理论上可以，但不实际。**

如果只调整相位，不调整频率：
- 每次相位偏差累积到一定程度，就需要调整
- 调整频率很高，系统不稳定
- 无法长期保持同步

**结论**：长期稳定的同步，必须同时进行相位和频率同步。

## 一个完整的频率同步示例

### 场景

- 主时钟频率：精确的125 MHz
- 从时钟本地晶振：标称125 MHz，实际125.00125 MHz（+10ppm误差）
- Sync报文间隔：1秒

### 初始状态

从时钟没有频率同步，本地时钟自由运行。

**第1个Sync**：

- 主时钟发送时间：T₁ = 0秒
- 从时钟接收时间：t₂₁ = 0秒（假设初始相位对齐）

**第2个Sync**：

- 主时钟发送时间：T₂ = 1秒
- 主时钟经过的时间：1秒
- 从时钟接收时间：t₂₂ = ?

由于从时钟晶振快了10ppm，实际经过的时间（从时钟视角）：

```
从时钟经过的时间 = 主时钟时间 × (从时钟频率 / 主时钟频率)
                = 1秒 × (125.00125 MHz / 125 MHz)
                = 1秒 × 1.00001
                = 1.00001秒

从时钟接收时间：t₂₂ = 0 + 1.00001 = 1.00001秒
```

测量相位偏差：

```
offset = t₂₂ - T₂ - meanDelay（假设meanDelay=0）
       = 1.00001 - 1
       = 0.00001秒
       = 10微秒
```

**频率偏差计算**：

```
频率偏差 = offset / 时间间隔
        = 10微秒 / 1秒
        = 10ppm
```

### 频率补偿

从时钟应用频率补偿：

```
frequency_adjustment = -10ppm = -0.00001
```

**第3个Sync**：

从时钟应用频率补偿后，本地时间：

```
调整后的从时钟时间 = 原始时间 × (1 + frequency_adjustment)
                   = 原始时间 × 0.99999
```

**验证**：

主时钟经过1秒（从第2个Sync到第3个Sync），从时钟原始时间经过1.00001秒。

调整后：

```
从时钟时间 = 1.00001 × 0.99999 = 1.00000秒
```

与主时钟一致！频率同步成功。

### 长期稳定性

假设频率补偿值固定为-10ppm。

**如果晶振频率漂移**（比如温度变化，频率变成+11ppm）：

- 频率偏差剩余：+1ppm
- 每秒累积误差：1微秒
- 需要持续测量和调整

**如果晶振频率稳定**：

- 频率偏差接近0
- 可以降低Sync报文频率
- 长期保持同步

---

## 小结：频率同步的核心要点

**为什么重要**：
- 保持长期稳定
- 支持保持模式
- 减少同步报文频率

**PTP频率同步方法**：
1. 从相位偏差推导频率偏差
2. 直接频率测量
3. 累积频率传输（可选）

**频率补偿实现**：
- 软件：维护补偿值，应用数学调整
- 硬件：NCO、PLL
- 混合：常用方案

**相位同步 vs 频率同步**：
- 相位同步：时间基准一致
- 频率同步：走时速度一致
- 长期稳定需要两者结合
